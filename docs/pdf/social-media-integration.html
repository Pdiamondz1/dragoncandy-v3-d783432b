Executive Summary

DragonCandy connects restaurants, creators, and brands for content delivery ��� but right now, the social media posting that makes that content valuable happens entirely outside the platform. This integration closes the loop: content gets created, approved, and published inside DragonCandy, with Donny handling the posting so nobody has to leave the platform.

The Gap

A creator shoots a reel for Sakura Sushi. The restaurant approves it inside DragonCandy. Then — nothing. The restaurant downloads the file, opens Instagram, writes a caption from scratch, guesses at hashtags, posts manually, and loses track of performance. The creator does the same dance to post it to their own channels. The brand sponsor has no visibility at all. Three parties, three separate workflows, zero coordination, zero data flowing back.

The Solution

Outstand.so integration brings posting, scheduling, analytics, and engagement inside DragonCandy — and Donny AI reduces every social action to a single sentence: "Donny, post today's special to Instagram and Google Business."

Integration Partner: Outstand.so — a unified, developer-first social media API supporting 10 platforms through a single REST API. White-label ready, usage-based pricing ($0.01/post after 1,000 included), and a 25-tool MCP server purpose-built for AI agent workflows like Donny.

DragonDash Rush Posting — The Premium Revenue Driver

The most expensive AI action in the social integration (multi-platform simultaneous posting with platform-specific captions) maps directly to DragonDash: a $25–50 rush surcharge when a restaurant or brand wants content live everywhere the moment it's approved. High-cost features pay for themselves. The cost architecture is designed so that DragonDash actions generate revenue that more than covers the Sonnet-tier AI cost.

Section 7: Market Context (2026)

This integration is designed for the market as it exists today — not 2022. The trends below directly informed platform prioritization, feature ordering, and the decision to go deep on short-form video and Google Business Profile before any other format.

Restaurant Trends

  • Instagram and Google Business Profile are non-negotiable. Local discovery for restaurants now runs through these two platforms more than any other. A restaurant without an active GBP presence loses direct search traffic daily.
  • TikTok influence is disproportionate to follower count. 61% of diners report TikTok food content directly influences where they eat — even one viral local food video reshapes a restaurant's booking curve.
  • Short-form video dominates all other formats. Reels, TikToks, and YouTube Shorts generate 3–8x the organic reach of static image posts. Every campaign deliverable should be a video-first asset.
  • Staff-led content (EGC) is emerging. Employee-generated content in hospitality is under-leveraged and showing strong performance — DragonCandy campaigns can seed this with creator-produced content that feels staff-originated.

Creator Economy Trends

  • $20.6 billion in 2026 — creator economy revenue growing at 16.2% YoY. The market is not slowing.
  • Shift toward long-term brand partnerships. One-off sponsorships are losing favor; creators and brands both prefer repeated campaigns with the same partners. DragonCandy's campaign repeat infrastructure supports this.

Section 10: Guiding Principles

Six principles that govern every implementation decision in this integration. When a technical choice is unclear, run it through these principles. The principles are ordered by priority — conflicts resolve by applying the higher-ranked principle.

1. Donny First, UI Second

Every social action must be achievable through Donny. The manual UI is the fallback, not the primary path. If you're building a UI for a social action, simultaneously ask: what's the Donny command for this?

2. Never Store Secrets Client-Side

Outstand API keys and OAuth tokens live in Supabase with AES-256 encryption. Edge Functions proxy all calls. No exceptions — this is a security requirement, not a preference.

3. White-Label Everything

Users see "DragonCandy Social" — never "Powered by Outstand." No third-party branding surfaces anywhere in the product. The integration is invisible infrastructure.

4. Build for Reuse

Phase 1 components (OAuth, posting, analytics) are role-agnostic. Phases 2–3 configure, not rebuild. Any new component should ask: can this be parameterized to work for all three roles?

5. Respect Existing Patterns

Follow the Toast POS integration pattern for OAuth token storage and Edge Function proxy design. Follow existing RLS patterns for all new tables. Consistency reduces the surface area for bugs.

6. RLS on Everything

All new social tables (social_connections, social_posts, social_post_analytics) follow existing Row Level Security patterns. Users can only access their own social data — no cross-tenant leakage.

Musk's Algorithm applied to this integration:

  • Deleted: Manual download-and-post workflow. Separate analytics dashboards per platform. Self-reported creator metrics.
  • Simplified: One API (Outstand) replaces 10 platform integrations. One Donny command replaces navigating 4 separate apps.
  • Accelerated: Content approval to social publish drops from ~20 minutes to <60 seconds.
  • Automated: Triple Social Hook fires automatically on content approval. Analytics cache refreshes on a schedule. Creator badge updates on account activity.

Appendix B: Technical Architecture Reference

Key Technical Decisions

Decision Detail
API Proxy All Outstand API calls go through Supabase Edge Functions. The client never touches the Outstand API directly — same pattern as the existing Toast POS integration.
Token Storage OAuth tokens encrypted with AES-256 in Supabase, following the existing toast_connections table pattern. Service role only — RLS prevents user access to raw tokens.
Outstand Auth Bearer token API key stored as a Supabase secret via supabase secrets set — never exposed to the frontend or committed to the repo.
Social Account Linking New social_connections table linking profile_id to Outstand's social_account_id per platform.
Post Records New social_posts table tracking all posts. Enables dashboard rendering without live Outstand calls.
Analytics Caching Pull analytics from Outstand periodically (hourly for recent posts, daily for historical). Cache in Supabase for fast dashboard rendering.
White-Label Outstand's white-label mode enabled. Users see "DragonCandy Social" — no third-party branding anywhere.
BYOK Architecture Schema supports Bring Your Own Keys: social_connections includes a nullable custom_app_credentials column for power users post-launch.
