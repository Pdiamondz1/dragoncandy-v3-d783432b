- [[verify_jwt Is Not Authorization]](concepts/anon-key-is-not-authorization.md) - **The Supabase anon key IS a valid JWT and ships in the frontend bundle**, so `verify_jwt:true` (the default for any function with no `config.toml` entry) only rejects a *missing* header - it never establishes a user. A service-role function that skips `auth.getUser()` therefore answers **anyone on the internet**. Proven on prod: `dragonshare-notify` returned 401 with no header and **200 with the public anon key**. Sibling of [[Service-Role Data Exposure]] (that page = a credential bypassing RLS; this = a platform gate that only looks like an auth check). A 100-function sweep found 18 candidates: 4 legitimately public (incl. `verify-package-order-escrow`, correctly guest-reachable and bound to Stripe `metadata.order_id`), 8 authorized by a mechanism the regex missed, **6 genuinely exposed**. **The scan blind spot is the lesson: `fire-promotion-social-hook` was cleared because it calls `getUser` - and never checks ownership. Authenticating is not authorizing.** One guard does not fit: the fix follows who legitimately calls it (`isAuthorizedIngest` for service-role-only; `getUser` + record-level ownership for browser; a per-operation split for both - `dragonshare-notify` is browser-called twice, so a blanket guard would have broken submission and decline). Also records **a read gate is not a write gate** (reusing `evaluateCampaignAccess` let a rejected applicant mint signed URLs over private deliverables), unpaired-ids x2, body-supplied cost attribution poisoning the AI kill-switch ledger, and a body-supplied dollar figure in a `role:assistant` Donny message. Traps: `.typecheck-ignore` hid 4 of 6 changed functions from the CI gate (compare `deno check` counts by hand); probe reachability, never impact; **zero Toast tables exist on prod**, which downgraded two findings. **All 7 functions are DEPLOYED and probe-verified on prod (2026-08-08)** - every one flipped 200/404/400 to **401** with the public anon key, and a real vs. bogus campaign id now return an identical 401 (existence oracle closed). The asymmetry is deliberate and driven by the CONSUMER — Codex caught a symmetric draft that would have announced "Funds held in escrow" on a plain status change. **The test for an anchor is never "how many columns" but "does every column this stamps on produce an event the reader reports".** No backfill (an UPDATE fires handle_updated_at + can trip enforce_single_slot_campaign); `DEFAULT now()` set AFTER `ADD COLUMN` or it stamps every existing row
