## Summary

Phase 1 of the Apple App Store workstream shipped: the Capacitor foundation that wraps the
existing web app in a native iOS shell so one codebase serves both dragoncandy.io (unchanged)
and a downloadable iPhone app. No business logic changed — this phase is scaffolding,
platform detection, and the WebView bridge. (Specs: 2026-06-01-apple-app-store-design.md;
plan: 2026-06-01-apple-app-store-phase1-capacitor-foundation.md; runbook:
docs/runbooks/capacitor-ios.md.)

## What Shipped (Phase 1)

- **Capacitor 6 packages**: `@capacitor/core`, `@capacitor/cli` (dev), `@capacitor/ios`
  (~6.2.x).
- **`capacitor.config.ts`**: `appId: io.dragoncandy.app` (permanent bundle identifier, must
  match App Store Connect), `appName: DragonCandy`, `webDir: dist`, iOS scheme `DragonCandy`.
- **iOS native project scaffold** committed (`ios/App/App.xcodeproj`, `Info.plist`, `Podfile`);
  `.gitignore` commits the project but ignores `Pods/`, `build/`, and the regenerated `public/`.
- **Platform detection**: `src/lib/platform.ts` (`isNativeApp()`, `getPlatformName()`,
  `isIOS()`) + a `useNativePlatform` hook exposing `isNative`/`isIOS`, read once on mount.
  Unit-tested with a mocked `@capacitor/core`.
- **CSP allowance** in `index.html` for `capacitor://localhost` (and `https://localhost`)
  across `default-src`/`connect-src`/`img-src`/`media-src` so the native WebView bridge works
  without loosening existing web allowances.
- **npm scripts**: `cap:sync` (build + `cap sync ios`), `cap:open` (`cap open ios`),
  `cap:copy` (build + `cap copy ios`).
- **Runbook** documenting the daily build/sync workflow and Mac prerequisites.

## The Strategy

- **One web codebase, two surfaces.** Desktop/web: unchanged site. iPhone: same web build in
  a WKWebView via Capacitor.
- **Payments split by surface.** Marketplace flows (boosts, campaign payments, DragonShare
  80/20) run on Stripe on both surfaces (real-world person-to-person services, guideline
  3.1.3(e)). Subscriptions/credits are **not** sold in-app at launch — users subscribe on web,
  the app reflects tier read-only — to avoid Apple's 30% cut (the most common rejection reason).
- **Guideline 4.2 (minimum functionality).** Not a bare wrapper: native value-adds
  (push/camera/share) are planned for Phase 2 — push also serves the camera-first North Star.
- **Route to store**: TestFlight → App Store submission (metadata, screenshots, privacy labels,
  reviewer demo accounts) → review → live.

## Key Decisions & Why

- **Capacitor over React Native / native rewrite.** Lean pre-revenue posture; Capacitor 6 is
  Vite/React-native and Lovable-compatible; one codebase, no second app to maintain.
- **Bundle ID `io.dragoncandy.app` fixed now.** Permanent identity; changing it later means
  re-registering with Apple.
- **Platform detection as the single source of truth** for "am I native?" — gates future
  native plugins and payment-hiding without user-agent sniffing. Platform is immutable at
  runtime, so it's read once.
- **CSP must include the `capacitor://` scheme** or the WebView load fails silently.
- **`ios/` committed, `Pods/`+`public/` ignored** — reproducible project; `Pods/` restored by
  `pod install` on a Mac, `public/` regenerated by every `cap sync`.
- **Scaffold on Windows, compile on Mac.** Capacitor CLI + `cap sync` run on Windows; only the
  actual Xcode build/sign needs macOS.

## Hard Prerequisites / Blockers (Phase 2+)

- **macOS or a cloud Mac** to compile/sign the `.ipa` (Codemagic recommended — Capacitor-native,
  free tier to start). Windows cannot build Xcode projects.
- **Apple Developer account** ($99/yr) to enroll, sign, and submit.
- App Store Connect record (bundle `io.dragoncandy.app`), hosted privacy policy/terms/EULA,
  App Privacy labels, 1024px icon, per-device screenshots, and three-role demo accounts for
  the reviewer.
