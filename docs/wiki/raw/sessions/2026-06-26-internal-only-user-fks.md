# Session — Internal-only AIOS users blocked by profiles FKs (2026-06-26)

PR: #180 (`fix/aios-internal-only-user-fks`). Both changes applied to prod during the
session; the PR is the durable record + review trail.

## Trigger

Adrian (`adrian.vella.jobs@gmail.com`), the **first internal-only AIOS user** invited via
the stakeholder flow (PR #178, `account_scope='internal'`), hit **"Google connect failed —
internal error"** on `/internal/workspace/callback`. Internal Donny chat also silently
failed for him.

## Root cause

Internal-only AIOS users intentionally have **no consumer `profiles` row** — the
`handle_new_user` trigger skips all consumer-profile creation when
`account_scope='internal'` ("a null profile is tolerated everywhere", PR #178 keystone).
But several AIOS-surface tables foreign-key `user_id → profiles(id)`, silently assuming
every internal user is also a consumer user. The two existing connected accounts (Joe,
Dame) both came in through the consumer app, so they *had* profiles and the FK was never
exercised by an internal-only user until Adrian.

Confirmed directly from prod logs (postgres), 65 ms before the proxy's 500:

```
ERROR: insert or update on table "google_workspace_accounts"
       violates foreign key constraint "google_workspace_accounts_user_id_fkey"
```
…then three identical `donny_conversations_user_id_fkey` violations ~20 s later (Adrian
opening Internal Donny).

## Why it presented as the opaque "internal error"

`google-workspace-proxy`'s catch-all did `err instanceof Error ? err.message : "internal
error"`. A Supabase **`PostgrestError` is a plain object, not an `Error` instance**, so the
real FK failure collapsed to the literal string `"internal error"` — in both the HTTP
response and the `console.error` log. The actual DB error never surfaced, which is why this
hid for weeks.

## Fixes (two commits, one incident)

### 1. Repoint AIOS FKs to `auth.users` (migration `20260626115951_repoint_aios_user_fks_to_auth_users`)

Repointed three AIOS-surface FKs from `profiles(id)` → `auth.users(id)`:
`google_workspace_accounts`, `donny_conversations`, `donny_tool_executions`.

- `profiles.id` **is** the `auth.users.id` (1:1 — `profiles.id` itself references
  `auth.users.id`), so the repoint is **non-destructive**: every row that satisfied the
  `profiles` FK already exists in `auth.users`. `ON DELETE CASCADE` preserved.
- Consumer-app tables (~31 other `profiles`-referencing FKs: campaigns, messages, file_\*,
  dragonshare…) are **deliberately left on `profiles(id)`** — internal-only users never
  write them.
- No PostgREST embed relies on the three repointed FKs (verified — the `profiles!…` embeds
  in `donny-chat` use `creator_id`, untouched). The Lovable-autogenerated `types.ts`
  `Relationships` metadata for these FKs is now cosmetically stale but harmless (left for
  regen).
- Applied to prod via Supabase MCP `apply_migration`; verified all three now reference
  `auth.users`.

### 2. Make proxy DB errors diagnosable (`google-workspace-proxy/errors.ts`)

New pure, vitest-tested `describeError(err)` normalizes any thrown value into `{ message,
code? }`: real `Error` → its message; a non-`Error` object (PostgrestError) → its
`message`+`code`; string/empty/null → sensible fallback. The catch now returns that and
logs the full error object. Internal-only surface; PostgrestError messages carry no
secrets.

- 6 unit tests (RED→GREEN via TDD).
- Deployed `google-workspace-proxy` **v19 → v20** via Supabase MCP (`verify_jwt=false`
  preserved); boot-checked (OPTIONS → 200, unauth POST → 401).

## Gotchas captured

- **A Supabase `PostgrestError` is NOT an `Error` instance** — `throw pgError` in an edge
  function with an `err instanceof Error ? … : "internal error"` catch silently erases the
  real DB error. Normalize non-Error throws.
- **MCP edge-fn deploy** needs the full transitive file set. `get_edge_function` returns the
  exact deployed files with names prefixed `functions/…` (NOT `supabase/functions/…`);
  re-send unchanged `_shared` deps verbatim and set `entrypoint_path` to match
  (`functions/google-workspace-proxy/index.ts`). A failed bundle keeps the old version.
- **The pre-push hook** re-asks for `npm run build`/`typecheck` each push (it can't see
  prior session runs) — run them, then the push proceeds.
