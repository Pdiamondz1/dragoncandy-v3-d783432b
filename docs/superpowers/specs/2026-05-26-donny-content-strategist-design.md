# Donny Content Strategist — Platform-Aware Campaign Generation & Posting Plans

## Problem

Three issues degrade the social media scheduling experience:

1. **Duplicate hashtags.** The `social-caption` edge function returns `caption` and `hashtags` as separate fields. The AI model also embeds hashtags inside the caption text. `SocialPostPrompt.generateCaption()` then appends the `hashtags` array, doubling them. The same issue exists in the draft-loading path where `loadDraft` appends `draft.hashtags` to `draft.caption` that may already contain them.

2. **No content strategy intelligence.** When a restaurant hits "Share" on delivered campaign content, all deliverables are dumped into one post prompt with one AI caption. There's no guidance on how to distribute content across post types (reels, stories, carousels), scheduling windows, or days. A campaign that produced 5 video clips gets treated as a single post — the restaurant has to figure out the content strategy themselves.

3. **Platform blindness.** Campaign generation (`donny-campaign-generate`) doesn't know what social platforms the restaurant has connected via Outstand. It might suggest TikTok-optimized content when Harbormill only has Instagram. The content strategy should be constrained to connected platforms from the start.

## Design

### 1. Bug Fix — Duplicate Hashtags

**Root cause:** Two paths produce the duplication:

- `generateCaption()` in `SocialPostPrompt.tsx`: reads `data.caption` (which the AI model stuffs with trailing hashtags) then appends `data.hashtags` array on top.
- `loadDraft` path: reads `draft.caption` (previously saved with hashtags baked in) then appends `draft.hashtags`.

**Fix:**

Before appending the `hashtags` array, strip any trailing hashtag block from the caption text. Detection regex: a block of `#\w+` tokens (possibly separated by spaces and newlines) at the end of the string.

```typescript
function stripTrailingHashtags(text: string): string {
  return text.replace(/(\n\n|\n)?(#\w+[\s]*)+$/g, '').trimEnd();
}
```

Apply this in both `generateCaption()` (to `data.caption`) and `loadDraft` (to `draft.caption`) before appending the `hashtags` array.

Additionally, separate caption and hashtags in component state:
- `caption: string` — text only, no hashtags
- `hashtags: string[]` — hashtag array, rendered separately below caption in a distinct teal style

This prevents re-contamination across save/load cycles.

### 2. Platform-Aware Campaign Generation

**Principle:** Donny never suggests content for platforms the restaurant hasn't connected.

**Data flow changes:**

1. **Type update** — add to `DonnyGenerateRequest`:
   ```typescript
   connected_platforms?: Array<{ platform: string; platform_handle: string | null }>
   ```
   Uses `platform_handle` (not `handle`) to match the existing `LocationSocialAccount` interface and `business_outstand_accounts.platform_handle` column. Platform values are always lowercase (`instagram`, `tiktok`, `x`, `youtube`, `facebook`) matching the CHECK constraint on `business_outstand_accounts.platform`.

2. **Hook update** — in `useCampaignCreator.submitInput()`, query `business_outstand_accounts` directly (not via hook, since `submitInput` is an async function, not a component). Query pattern:
   ```typescript
   const { data: accounts } = await supabase
     .from('business_outstand_accounts')
     .select('platform, platform_handle')
     .eq('user_id', user.id)
     .eq('status', 'active');
   const connected_platforms = (accounts ?? []).map(a => ({
     platform: a.platform,
     platform_handle: a.platform_handle,
   }));
   ```
   The `org_unit_id` filter is omitted here because the campaign itself may span multiple locations. If the query fails, proceed without `connected_platforms` (the edge function treats missing platforms as "generate for all") — this is non-blocking to campaign creation.

3. **Edge function update** — in `donny-campaign-generate/index.ts`, inject platform constraints into the Anthropic system prompt:
   ```
   CONNECTED SOCIAL MEDIA PLATFORMS:
   ${platforms.map(p => `- ${p.platform} (@${p.handle})`).join('\n')}
   
   Generate content strategy, recommended_platforms, and deliverables
   ONLY for the connected platforms listed above. Do not suggest content
   for platforms the business has not connected.
   ```

4. **Zero-platform handling** — if no connected platforms, still generate the campaign but set `content_strategy: null`. The UI shows an inline nudge: "Connect a social account in Settings to unlock auto-scheduling and content strategy."

### 3. Content Strategy in Campaign Brief

Each `CampaignIdea` gains a `content_strategy` block, generated by the AI based on campaign type, connected platforms, and deliverable recommendations.

**Type addition to `CampaignIdea`:**

```typescript
type StrategyPurpose =
  | 'hero_showcase'       // Main content piece — the star of the campaign
  | 'behind_scenes'       // Kitchen prep, setup, process — builds authenticity
  | 'teaser_hype'         // Pre-launch anticipation builder
  | 'follow_up'           // Post-hero reminder or call-to-action
  | 'testimonial'         // Customer reaction, review clip
  | 'menu_highlight'      // Individual dish/item spotlight
  | 'ambient_vibe'        // Atmosphere, decor, music — mood-setting
  | 'event_coverage';     // Live event or special occasion

interface ContentStrategyPost {
  content_type: ContentType;    // 'reel' | 'story' | 'carousel' | 'photo'
  platform: Platform;           // 'instagram' | 'tiktok' | 'youtube' | 'facebook' | 'x'
  purpose: StrategyPurpose;     // categorized role in the campaign strategy
  description: string;          // what the creator should deliver for this slot
  day_offset: number;           // relative to when user clicks "Share" (0 = today, 1 = tomorrow, -1 = yesterday)
}

interface ContentStrategy {
  posts: ContentStrategyPost[];
  cadence: 'spread' | 'burst' | 'ramp';
  duration_days: number;
  reasoning: string;            // Donny explains the strategy
}
```

The `cadence` field guides the posting plan generator:
- `spread`: evenly distributed across `duration_days`
- `burst`: concentrated within 24-48 hours
- `ramp`: builds up to a peak day (stories first, then hero reel)

**Storage:** The content strategy is stored in `campaigns.ai_analysis` JSONB field alongside existing data (business_context, brand_fields, etc). No new columns on `campaigns` needed.

**UI in campaign brief:** The launchpad screen shows the content strategy as part of the campaign idea card. The creator sees the deliverable breakdown (what to create), and the restaurant sees the posting plan outline (when it'll be posted).

### 4. Content Posting Plan Edge Function

**New edge function:** `content-posting-plan`

**Purpose:** When deliverables arrive and the restaurant hits "Share," this function maps deliverables to the stored content strategy, generates platform-adapted captions, and assigns optimal posting times.

**Input:**
```typescript
{
  deliverables: Array<{
    url: string;
    mime_type: string;
    filename?: string;
    file_id?: string;
  }>;
  content_strategy: ContentStrategy | null;  // from campaigns.ai_analysis
  connected_platforms: Array<{ platform: string; handle: string }>;
  campaign: {
    id: string;
    title: string;
    type: CampaignType;
    deadline?: string;
    description?: string;
    key_messages?: string[];
    hashtags?: string[];
  };
  user_id: string;
}
```

**Logic:**
1. If `content_strategy` exists, map each deliverable to a strategy slot by content type match. Extra deliverables get assigned to the nearest matching slot or appended as additional posts.
2. If no strategy (legacy campaigns), analyze deliverable media types and generate a default strategy: videos → reels, photo groups → carousels, single photos → feed posts.
3. For each post in the plan, call Anthropic to generate a platform-adapted caption. Instagram gets hashtag-heavy captions, TikTok gets trending-style hooks, YouTube gets SEO-friendly descriptions, etc.
4. Assign optimal posting times using static best-practice rules per platform and content type.

**Static time rules (initial set):**
| Platform | Content Type | Best Times |
|----------|-------------|------------|
| Instagram | Reel | Tue/Thu 11am-1pm, Sat 9-11am |
| Instagram | Story | Mon-Fri 8-9am |
| Instagram | Carousel | Wed/Fri 5-7pm |
| Instagram | Feed post | Mon/Wed 12-2pm |
| TikTok | Video | Daily 7-9pm |
| YouTube | Short | Tue/Thu 2-4pm |
| Facebook | Post/Reel | Mon/Wed/Fri 1-3pm |
| X/Twitter | Post | Weekdays 8-10am, 12-1pm |

Times are in the restaurant's local timezone. Resolution strategy: the `content-posting-plan` function uses `business_context.location.city` + `business_context.location.state` to look up the IANA timezone via a static US city→timezone map (covers the initial metro-by-metro launch). For unresolvable locations, default to `America/New_York`. The timezone is passed to the scheduling logic, not stored permanently — if the restaurant's location changes, future plans use the new timezone. No external geocoding API needed for v1.

**Output:**
```typescript
{
  plan_id: string;  // UUID for plan_group_id
  posts: Array<{
    content_type: ContentType;
    platform: Platform;
    caption: string;
    hashtags: string[];
    media_urls: string[];
    scheduled_at: string;        // ISO datetime
    ai_reasoning: string;        // why this time/type
    plan_order: number;          // sequence in plan
    purpose: string;             // from strategy or generated
  }>;
  strategy_summary: string;      // human-readable plan overview
}
```

### 5. Posting Plan Review UI

**Component:** `PostingPlanReview` replaces the single-post `SocialPostPrompt` when a campaign has delivered content.

**Trigger logic in `DeliverablesArchive.tsx`:**
- If campaign has stored `content_strategy` in `ai_analysis` → show `PostingPlanReview`
- If no strategy (legacy campaigns) → fall back to existing `SocialPostPrompt` single-post flow

**Plan review layout:**
- Header: "Donny's Posting Plan" + campaign title
- Strategy summary card: brief overview of the plan (e.g., "3 reels over 5 days with hype stories")
- Scrollable list of proposed posts, each showing:
  - Media thumbnail (via `MediaPreviewGrid` pattern, single hero item per post)
  - Content type badge (Reel, Story, Carousel, Post) — teal pill
  - Platform badge — platform-colored pill
  - Suggested date/time — editable via `datetime-local` input
  - AI caption — expandable, editable inline via textarea
  - Remove button (X) per post
- Bottom actions:
  - "Schedule All" (primary, full-width teal pill) — creates all `donny_scheduled_posts` rows with shared `plan_group_id`
  - "Let Donny Decide" (secondary, outlined) — regenerates the entire plan
- After scheduling: transitions to `ScheduleConfirmation` showing plan summary + "View on Calendar"

**Responsive:** Sheet (mobile) / Dialog (desktop) matching existing `SocialPostPrompt` pattern. Mobile Sheet uses `max-h-[85vh]` with scrollable content area. Desktop Dialog uses `sm:max-w-lg max-h-[85vh]` (wider than single-post dialog to accommodate plan list).

### 6. Share → Plan Generation Data Flow

```
User clicks "Share" in DeliverablesArchive
  │
  ├── Fetch campaign.ai_analysis from Supabase
  │     └── Has content_strategy?
  │           ├── YES → Open PostingPlanReview
  │           └── NO  → Open SocialPostPrompt (legacy single-post flow)
  │
  ▼ (PostingPlanReview mounts)
  │
  ├── Fetch connected platforms (business_outstand_accounts, status='active')
  │     └── Zero platforms? → Show nudge, stop
  │
  ├── Call content-posting-plan edge function with:
  │     { deliverables, content_strategy, connected_platforms, campaign metadata }
  │     └── Show loading skeleton while generating
  │
  ├── Receive plan: { plan_id, posts[], strategy_summary }
  │     └── Error? → Show error + "Try Again" button
  │              → On retry: re-call content-posting-plan
  │              → After 2 failures: fall back to SocialPostPrompt
  │
  ▼ (User reviews plan)
  │
  ├── User edits: change times, edit captions, remove posts
  │
  ├── "Let Donny Decide" → DISCARDS all user edits, re-calls
  │     content-posting-plan from scratch. Confirm dialog first:
  │     "This will replace your edits with a new plan. Continue?"
  │
  ├── "Schedule All" →
  │     ├── Generate plan_group_id (UUID)
  │     ├── For each post: crossPost.mutate() to Outstand API
  │     ├── For each post: INSERT donny_scheduled_posts with plan_group_id
  │     ├── On all success → show ScheduleConfirmation with plan summary
  │     └── On partial failure → show which posts failed, offer retry
  │
  └── "Done" → close dialog
```

**Cost note:** The `content-posting-plan` function calls Anthropic once for the entire plan (a single prompt that generates all captions), not once per post. A 5-post plan costs roughly the same as 1 single-post caption generation. "Let Donny Decide" re-runs this single call.

### 7. Data Model Changes

**`donny_scheduled_posts` — new columns (migration):**
- `plan_group_id uuid DEFAULT NULL` — freeform grouping key (no FK, no referential integrity — just a shared UUID generated client-side when "Schedule All" is pressed)
- `plan_order int DEFAULT NULL` — sequence within the plan (not unique-constrained; if NULL, sort by `scheduled_at` then `created_at`)
- Index: `CREATE INDEX idx_scheduled_posts_plan_group ON donny_scheduled_posts (plan_group_id) WHERE plan_group_id IS NOT NULL;`

**`DonnyGenerateRequest` type — new optional field:**
- `connected_platforms?: Array<{ platform: string; handle: string }>`

**`CampaignIdea` type — new optional field:**
- `content_strategy?: ContentStrategy | null` (see Section 3 for type definition)
- `null` when no connected platforms; `undefined` for legacy campaigns created before this feature
- All existing UI code that reads `CampaignIdea` is unaffected — the field is optional and only consumed by the new `PostingPlanReview` component

**Backward compatibility:** Legacy campaigns (created before this feature) have no `content_strategy` in `ai_analysis`. The "Share" flow checks `campaign.ai_analysis?.content_strategy`:
- Present → show `PostingPlanReview` (new multi-post flow)
- Missing/null → fall back to existing `SocialPostPrompt` (single-post flow, unchanged)

**No new tables.** The `content_type` column on `donny_scheduled_posts` already supports reel/story/carousel/photo/video/tweet/thread. The `campaigns.ai_analysis` JSONB field stores the content strategy without schema changes.

### 8. Calendar Plan Grouping

Posts scheduled via the posting plan share a `plan_group_id`. The calendar UI reflects this:

- Posts in the same plan get a subtle visual indicator (shared left-border color or a small plan badge)
- Clicking a grouped post in `PostManagementPanel` shows a "Part of [Campaign Title] plan (X posts)" context line
- "Cancel Plan" action available — cancels all posts with the same `plan_group_id`

### 9. Zero-Platform Graceful Handling

**In campaign creation — Launchpad screen (`src/components/campaign-creator/LaunchpadScreen.tsx`):**
- If `connected_platforms` array is empty: show an amber banner below the campaign idea card: "Connect a social account in Settings to unlock auto-scheduling and content strategy"
- Banner includes a "Go to Settings →" link pointing to `/dashboard/business/settings` (or `/dashboard/brand/settings` for brands)
- Campaign still launches normally — the strategy is just absent

**In "Share" flow — `DeliverablesArchive.tsx`:**
- Before opening `PostingPlanReview` or `SocialPostPrompt`, check connected platforms
- If zero platforms: render an inline card (same amber style) in place of the dialog trigger button: "Connect your Instagram (or other social accounts) in Settings to share content directly"
- Link to Settings. No dialog opens.

## Verification

1. Open "Share" dialog — hashtags appear exactly once, not duplicated
2. Create campaign with only Instagram connected — all deliverables and strategy target Instagram, no other platforms suggested
3. Create campaign with zero connected accounts — nudge to connect appears, no strategy generated
4. Campaign idea shows content strategy (e.g., "3 reels over 5 days + 2 stories")
5. "Share" on delivered content → posting plan review shows multi-post plan with per-post captions, times, and content types
6. Edit caption, change time, remove individual posts in plan review
7. "Schedule All" creates grouped `donny_scheduled_posts` rows, confirmation shows, posts appear on calendar
8. Calendar shows plan-grouped posts with visual indicator
9. "Cancel Plan" removes all posts in group
10. All UI works on both desktop and mobile viewports
