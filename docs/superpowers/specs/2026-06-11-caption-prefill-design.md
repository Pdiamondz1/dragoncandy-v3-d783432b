# Caption field + brief caption pre-fill (Content Engine Phase B, Slice 3) — Design Spec

**Date:** 2026-06-11
**Status:** Approved Design
**Approach:** Add an always-on optional caption field to the DragonShare submit form; pre-fill (editable) from the brief's `sample_caption` + `hashtags` when the creator arrives via the "Make it & submit" CTA
**Phase:** Content Engine Phase B, Slice 3 (completes the brief → submission action)
**Prerequisites:** Slice 1 (`content_briefs` + `content-strategy-recommend` + `ContentIdeaCard`, live) and Slice 2 (the "Make it & submit" CTA + `dragonshare_posts.source_brief_id` + restaurant pre-fill desktop/mobile, live in prod).

---

## Overview

Slice 2 deep-links the brief into the DragonShare submit flow with the restaurant pre-selected, but the
brief's **ready-to-post caption** (`sample_caption`) and **hashtags** have nowhere to go: the DragonShare
submit form has **no caption input** (deliberate upload-first single-screen design), and `handleSubmit`
never writes a caption. So the creator sees the great caption Donny wrote on the brief, lands in the submit
flow, and has to retype it elsewhere.

Slice 3 closes that: it adds a single **always-on, optional caption field** to the submit form (for every
creator), and when the creator arrives from a brief it is **pre-filled and editable** with the brief's
`sample_caption` + `hashtags`. The caption is stored in the **existing** `dragonshare_posts.caption` column
(text) — no migration. This makes the brief → DragonShare path one continuous motion: the brief writes the
caption, the creator tweaks and submits.

**What this deletes:** retyping the brief's caption; the brief→submit dead-end for the caption.
**What this simplifies:** create→caption→submit collapses into the same single screen.
**What it automates:** the caption itself is generated by the brief and carried into the post.
**Keystrokes removed:** from "retype the caption Donny already wrote" (dozens–hundreds of keystrokes) to
**zero** for the from-brief path — the caption arrives pre-filled and editable.

---

## Decisions (brainstorm, 2026-06-11)

| Decision | Choice |
|----------|--------|
| Field scope | **Always-on, optional.** One caption `<textarea>` visible on the submit form for every creator (blank is allowed). One consistent form; the field is the natural home for the captured brief caption. (Rejected: only-when-from-a-brief, collapsible toggle — more conditional UI state for little gain.) |
| Caption transport | **Refetch, not URL param.** `usePreselectedOrg` already fetches the `content_briefs` row by id; extend its `select` to also read `brief`. Captions are long/multi-line — unfit for the URL. |
| What pre-fills | **`sample_caption` + `hashtags` joined** on a blank line: `\`${sample_caption}\n\n${hashtags.join(' ')}\``. Hashtags appended only when present. |
| Storage | **Existing `dragonshare_posts.caption` column** (text, nullable). **No migration.** No separate hashtags column — hashtags ride in the caption text. |
| Pre-fill semantics | **Seed once, then the creator owns it.** The brief caption seeds the field on first arrival; subsequent re-renders must not clobber the creator's edits (same capture-once pattern Slice 2 used for `sourceBriefId`). |

## C1 — `composeCaption` (pure helper)

A small pure function (own file, e.g. `src/lib/composeCaption.ts`) so it is unit-testable without React:

```ts
/** Join a brief's caption with its hashtags for pre-filling the DragonShare caption field.
 *  Hashtags are appended on a blank line only when present; each is normalized to start with '#'. */
export function composeCaption(sampleCaption?: string | null, hashtags?: string[] | null): string {
  const caption = (sampleCaption ?? '').trim();
  const tags = (hashtags ?? [])
    .map((t) => String(t).trim())
    .filter(Boolean)
    .map((t) => (t.startsWith('#') ? t : `#${t}`));
  if (!caption && tags.length === 0) return '';
  if (tags.length === 0) return caption;
  if (!caption) return tags.join(' ');
  return `${caption}\n\n${tags.join(' ')}`;
}
```

Tests: caption-only; caption+hashtags; hashtags missing `#`; empty/missing both → `''`; whitespace-only
caption with tags → tags only.

## C2 — `useDragonShareSubmitForm`

Signature becomes `useDragonShareSubmitForm(sourceBriefId?: string | null, prefillCaption?: string | null)`.

- **State:** `const [caption, setCaption] = useState('')` — exposed in the return so the textarea binds to it.
- **Seed once (capture pattern, mirrors `capturedBriefId`):**
  ```ts
  const seededRef = useRef(false);
  useEffect(() => {
    if (prefillCaption && !seededRef.current) {
      setCaption(prefillCaption);
      seededRef.current = true;
    }
  }, [prefillCaption]);
  ```
  A `ref` guard (not just "seed if empty") so we seed exactly once and never overwrite the creator's later
  edits — even if they clear the field deliberately. (Implementer note: `useRef` is already imported.)
- **Draft persistence:** add `caption` to the `DragonShareDraft` interface, `EMPTY_DRAFT`, `loadDraft`, the
  sync `useEffect` (and its empty-draft early-out condition so a caption-only draft still persists), so the
  caption survives the same navigation round-trips `uploadedUrl`/`postUrl` already survive.
- **reset():** add `setCaption('')` (the post-submit clear) — leave `seededRef` as-is; the component unmounts
  on navigation, so a fresh arrival re-seeds.
- **handleSubmit:** add `caption: caption.trim() || null` to the `mutateAsync` payload.
- **Return:** add `caption` and `setCaption` to the returned object.

## C4 — `usePreselectedOrg` (`CreatorDragonShare.tsx`)

The existing brief-validation query selects only `organization_id`. Extend it:

```ts
const { data: briefRow } = useQuery({
  queryKey: ['preselected-brief', briefId],
  queryFn: async (): Promise<{ organization_id: string; brief: ContentBriefShape } | null> => {
    if (!briefId) return null;
    const { data, error } = await supabase
      .from('content_briefs')
      .select('organization_id, brief')
      .eq('id', briefId)
      .maybeSingle();
    if (error || !data) return null;
    return data as { organization_id: string; brief: ContentBriefShape };
  },
  enabled: !!briefId,
});

const briefOrgId = briefRow?.organization_id ?? null;
const sourceBriefId = briefId && org && briefOrgId === org.id ? briefId : null;
const prefillCaption =
  sourceBriefId && briefRow
    ? composeCaption(briefRow.brief?.sample_caption, briefRow.brief?.hashtags)
    : null;

return { org: org ?? null, sourceBriefId, prefillCaption: prefillCaption || null };
```

- `ContentBriefShape` is a minimal local type for the two fields we read
  (`{ sample_caption?: string; hashtags?: string[] }`) — the `brief` jsonb is `Json`, so cast/narrow rather
  than introducing a hard dependency on the edge function's type. No `any`.
- `prefillCaption` is derived **only** when `sourceBriefId` is valid (owned + org-matched), so a stale or
  hand-edited URL never injects a caption — same guard that protects the link.
- Call site: `const { org: preselectedOrg, sourceBriefId, prefillCaption } = usePreselectedOrg();`
- Pass `prefillCaption` to **both** the desktop inline form and the mobile sheet alongside the existing
  `preselectedOrg` + `sourceBriefId` props.

## C5 — Form surfaces (`DragonShareInlineForm`, `DragonShareSubmitSheet`)

- Both add `prefillCaption?: string | null` to Props and pass it as the 2nd hook arg:
  `useDragonShareSubmitForm(sourceBriefId, prefillCaption)`.
- Both render a caption `<textarea>` bound to `form.caption` / `form.setCaption`, placed after the
  upload/link area and before (or beside) the restaurant selector — consistent with the accepted mockup:
  - Label "Caption (optional)"; placeholder e.g. "Add a caption…".
  - Design system: rounded (`rounded-2xl`/`rounded-xl`), white field, teal focus ring, **no gray**
    backgrounds/borders (use teal/pink-adjacent + brand neutrals); `dc-*` tokens.
  - Sensible `rows` (e.g. 3–4) and a max length guard if the column/UX warrants (otherwise free text).
  - Desktop changes via `lg:` where the inline form differs; mobile base classes in the sheet. Test both.
- No change to upload, platform detection, boost-or-pass, notify, or the rest of the flow — `caption` rides
  along as one optional field.

## Reuse / guardrails

- **Reuse:** the entire Slice 2 plumbing (`usePreselectedOrg` brief fetch + validation, the `preselectedOrg`/
  `sourceBriefId` prop threading, the capture-once pattern), `useDragonShareSubmitForm`,
  `useSubmitDragonSharePost`, the `sessionStorage` draft, React Query.
- **No migration / no RLS change:** `dragonshare_posts.caption` already exists; the creator writes their own
  row. **No auth/schema drops.**
- **Design system:** `dc-*` tokens, rounded fields, teal/pink, **no gray**; desktop `lg:`/`xl:`, mobile base;
  verify both viewports.
- **North-star aligned:** the field is optional (doesn't force typing on a blank submit) and, on the
  from-brief path, removes typing entirely (pre-filled).
