## 3. Improvements
- **#1 capacity move — build the multi-IP runner matrix (spec §4b fan-out).** A single GH runner caps at
  ~312 concurrency on egress, ~2.5–5× below the 800–1,500-peak-concurrent band that brackets 50K DAU. Until
  load is fanned across N runner IPs and summed, **the DB cannot be pushed to its knee** and no credible
  DB-ceiling / 50K proof is possible. This run is the evidence that justifies that build.
- **Tier recommendation: DEFER.** Upgrading compute now would show zero improvement — the DB is 91% idle.
  Tier-stepping only becomes meaningful once the matrix actually loads the DB.
- **Query/RLS optimizations (pre-emptive):** remediate `auth_rls_initplan` (wrap `auth.uid()` etc. in a
  scalar subquery) and consolidate `multiple_permissive_policies` on the hot tables first — `campaigns`,
  `dragonshare_posts`, `public_creator_profiles`, `conversations` — the endpoints that will be hottest at scale.
- **Harness:** upload `sim/.load-findings.json` as a GH artifact (≈4-line `actions/upload-artifact` step) so
  matrix runs capture full breakage **signatures**, not just the console counts this single-runner pass gave.
